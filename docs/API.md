# API نسخه ۱ — حساب لند

مرجعِ رسمیِ ساختِ اپ اندروید، iOS، و هر مشتری دیگر.

نشانی پایه:

```
https://hesab.stland.ir/api/v1
```

این شکل به یک قاعده‌ی rewrite در nginx نیاز دارد (`deploy/nginx-api.sh --apply`).
اگر آن قاعده نباشد یا روزی از دست برود، این شکل **همیشه** کار می‌کند:

```
https://hesab.stland.ir/api/v1/index.php?p=transactions
```

پارامترهای دیگر عادی کنارش می‌آیند: `?p=transactions&per_page=20`.

> **اپ باید هر دو را بلد باشد.** اول آدرس تمیز؛ اگر ۴۰۴ـِ nginx گرفت (بدنه‌ی HTML، نه
> JSON)، از آن به بعد `?p=` را استفاده کند. فایل سایتِ nginx ممکن است بازنویسی شود
> (مثلاً با certbot) و اپ‌هایی که روی گوشی مردم نصب‌اند نباید با آن بخوابند.
>
> ⚠ **`/api/v1/index.php/transactions` روی nginx کار نمی‌کند** — در نسخه‌ی اول این سند
> اشتباه نوشته شده بود. قاعده‌ی `location ~ \.php$` با آدرسی که به `/transactions`
> ختم می‌شود تطابق ندارد، پس ۴۰۴ می‌گیرد. فقط روی سرور توسعه‌ی PHP کار می‌کند.
> `p` یک نام رزرو شده است و برای چیز دیگری استفاده نکنید.

## قاعده‌ی نسخه — پیش از هر چیز این را بخوانید

اپی که روی گوشی کاربر نصب شده را **نمی‌شود مجبور به به‌روزرسانی کرد.** پس:

**مجاز در v1** — افزودن کلید تازه به پاسخ، افزودن پارامتر اختیاری، افزودن اندپوینت تازه.

**ممنوع در v1** — حذف یا تغییر نام کلید، تغییر نوع یا معنای یک مقدار، اجباری کردن
پارامتری که پیش‌تر اختیاری بود، تغییر کد وضعیت.

هر کدام از این‌ها لازم شد → `api/v2/` ساخته می‌شود و v1 تا وقتی اپ‌های قدیمی زنده‌اند
سر جایش می‌ماند.

> پوشه‌ی `api/` (بدون نسخه) لایه‌ی داخلیِ AJAX خودِ سایت است و آزادانه با صفحه‌ها عوض
> می‌شود — چهار تای آن اصلاً HTML برمی‌گردانند نه JSON. **هرگز از آن‌ها استفاده نکنید.**

## شکل پاسخ

موفق:

```json
{ "ok": true, "data": { } }
```

ناموفق:

```json
{ "ok": false, "error": { "code": "invalid_credentials", "message": "نام کاربری یا رمز عبور اشتباه است." } }
```

`code` ماشین‌خوان است و ترجمه نمی‌شود؛ `message` فارسیِ قابل نمایش.
**اپ باید روی `code` تصمیم بگیرد، نه روی متن** — وگرنه اصلاح یک غلط املایی در پیام،
منطق اپ را می‌شکند.

هر پاسخ سرآیند `X-API-Version` دارد.

### کدهای خطا

| code | وضعیت | معنا |
|---|---|---|
| `unauthenticated` | ۴۰۱ | توکن نیست، نامعتبر است، یا باطل شده |
| `invalid_credentials` | ۴۰۱ | نام کاربری یا رمز اشتباه |
| `too_many_attempts` | ۴۲۹ | سد حدس رمز فعال شده؛ پیام مدت را می‌گوید |
| `forbidden` | ۴۰۳ | رکورد مالِ کاربر دیگری است |
| `not_found` | ۴۰۴ | رکورد یا آدرس وجود ندارد |
| `method_not_allowed` | ۴۰۵ | متد اشتباه (سرآیند `Allow` را ببینید) |
| `validation` | ۴۲۲ | ورودی نامعتبر؛ `message` دلیل را می‌گوید |
| `invalid_json` | ۴۰۰ | بدنه JSON معتبر نیست |
| `api_unavailable` | ۵۰۳ | migration اجرا نشده |
| `server_error` | ۵۰۰ | خطای سمت سرور |

## تاریخ و مبلغ

**تاریخ همیشه هر دو شکل را دارد:**

```json
"date": { "iso": "2026-08-31", "jalali": "۱۴۰۵/۰۶/۰۹" }
```

هنگام **فرستادن**، همیشه `iso` (میلادی) بفرستید.

> ⚠ **اپ نباید خودش تاریخ شمسی را حساب کند.** منطق تبدیل الان دو بار در پروژه هست
> (PHP و `assets/js/jalali-datepicker.js`) و `tests/test_jalali_parity.php` هم‌خوانی‌شان
> را می‌سنجد. پیاده‌سازی سوم بیرون از پوشش آن تست می‌ماند و دیر یا زود یک روز اختلاف
> پیدا می‌کند. تبدیل همیشه سمت سرور انجام می‌شود.

**مبلغ همیشه عدد صحیح است** (تومان، بدون اعشار). ستون‌ها `BIGINT` اند. هرگز به `double`
نریزید — مقدارهای بزرگ دقتشان را از دست می‌دهند و جمع‌ها نمی‌خوانند. در Dart از `int`
استفاده کنید.

هنگام فرستادن، مبلغ را می‌شود با ارقام فارسی و جداکننده هم فرستاد (`"۱۲٬۵۰۰"`)؛
سرور با `sanitizeAmount()` پاکش می‌کند.

## احراز هویت

### `POST /auth/login`

بدون توکن.

```json
{ "username": "ali", "password": "…", "device_name": "Pixel 8", "platform": "android" }
```

`username` نام کاربری یا ایمیل را می‌پذیرد. `device_name` و `platform` اختیاری‌اند
(`android` / `ios` / `web` / `desktop`).

```json
{ "ok": true, "data": {
    "token": "3f2a….a91b…",
    "expires_in_days": 90,
    "user": { "id": 2, "username": "ali", "full_name": "علی", "role": "user" }
} }
```

> **رشته‌ی توکن فقط همین یک بار دیده می‌شود.** در حافظه‌ی امنِ سیستم‌عامل نگهش دارید —
> Keystore/EncryptedSharedPreferences روی اندروید، Keychain روی iOS — نه در فایل ساده
> یا SharedPreferences معمولی.

تلاش ناموفق در سدِ حدس رمز شمرده می‌شود، دقیقاً مثل صفحه‌ی ورود سایت (۵ بار برای هر
نام کاربری و ۲۰ بار برای هر IP در ۱۵ دقیقه).

### بقیه‌ی درخواست‌ها

```
Authorization: Bearer <token>
```

عمر توکن ۹۰ روز است و با هر استفاده تمدید **نمی‌شود**؛ بعد از انقضا باید دوباره وارد شد.
حداکثر ۱۰ توکن زنده برای هر کاربر نگه داشته می‌شود (قدیمی‌ترها خودکار می‌روند).

### `POST /auth/logout`

توکنِ همین دستگاه را باطل می‌کند. دستگاه‌های دیگر دست‌نخورده می‌مانند.

### `GET /me`

```json
{ "ok": true, "data": { "id": 2, "username": "ali", "full_name": "علی", "role": "user" } }
```

### `GET /ping`

بدون توکن. برای سنجش دسترسی و نسخه:

```json
{ "ok": true, "data": { "api_version": 1, "today": {…}, "auth_ready": true } }
```

## تراکنش‌ها

### `GET /transactions`

| پارامتر | نمونه | توضیح |
|---|---|---|
| `from` / `to` | `2026-08-01` | بازه‌ی تاریخ میلادی |
| `type` | `income` یا `expense` | |
| `category_id` / `wallet_id` | عدد | |
| `page` | `1` | پیش‌فرض ۱ |
| `per_page` | `50` | پیش‌فرض ۵۰، سقف ۱۰۰ |

```json
{ "ok": true, "data": {
  "items": [ {
      "id": 243, "type": "expense", "amount": 25000,
      "title": "خرید", "note": null,
      "date": { "iso": "2026-08-31", "jalali": "۱۴۰۵/۰۶/۰۹" },
      "category": { "id": 4, "name": "خوراک", "icon": "🍎", "color": "#e74c3c" },
      "wallet": { "id": 2, "name": "کیف پول" },
      "created_at": "2026-08-31 18:07:55"
  } ],
  "page": { "number": 1, "per_page": 50, "total": 7, "pages": 1 }
} }
```

`category` و `wallet` می‌توانند `null` باشند.

### `GET /transactions/{id}`

همان شکلِ یک ردیف. اگر مالِ کاربر دیگری باشد **۴۰۴** می‌گیرد، نه ۴۰۳ — تا وجودِ رکوردِ
دیگران لو نرود.

### `POST /transactions`

```json
{ "type": "expense", "amount": 25000, "title": "خرید",
  "transaction_date": "2026-08-31", "note": "…",
  "category_id": 4, "wallet_id": 2 }
```

`note`، `category_id` و `wallet_id` اختیاری‌اند. پاسخ **۲۰۱** با `{ "id": … }`.

> دسته‌بندی یا حسابی که مالِ کاربر نباشد **خطا نمی‌دهد، `null` می‌شود.** این رفتار عمدی
> و از پیش موجود است: پول نباید به خاطر یک شناسه‌ی نامعتبر ثبت نشود.

### `PATCH /transactions/{id}`

همان فیلدها، بدون `wallet_id` — **ویرایش حساب را عوض نمی‌کند** (مثل فرم ویرایش سایت).

اگر شبکه یا پراکسی `PATCH` را قورت داد، `POST` روی همان آدرس هم پذیرفته می‌شود.

## حساب‌ها و دسته‌بندی‌ها

### `GET /wallets`

```json
{ "ok": true, "data": {
  "items": [ { "id": 2, "name": "کیف پول", "kind": "cash", "kind_label": null,
               "bank_name": null, "color": "#16794f",
               "balance": -2500000, "is_active": true } ],
  "total_balance": 9800000
} }
```

`balance` از `walletBalances()` می‌آید — تنها مرجع موجودی در کل پروژه — و چک پاس‌شده و
پرداخت طلب و بدهی را هم حساب می‌کند. می‌تواند منفی باشد.

> **شماره‌ی کارت، شماره‌ی حساب و شبا عمداً در این اندپوینت نمی‌آیند.** حساس‌اند و در
> سایت هم فقط در نمای کارت باز می‌شوند.

### `GET /categories`  ‌ (اختیاری: `?type=income|expense`)

```json
{ "items": [ { "id": 4, "name": "خوراک", "type": "expense",
               "icon": "🍎", "color": "#e74c3c", "is_default": true } ] }
```

`is_default` یعنی دسته‌ی پیش‌فرضِ برنامه است (کاربر نمی‌تواند حذفش کند)؛ در برابرِ
دسته‌ی شخصیِ خودش.

## پیامکِ بانک (کارگرِ پس‌زمینه‌ی اپ اندروید)

فقط برای `SmsSync.java` / `assets/js/sms-worker.js` — `docs/decisions/mobile.md`.
کلیدش **محدود** است (`scope = sms`) و جز این سه مسیر چیزی را باز نمی‌کند (۴۰۳ با
کدِ `scope`)؛ کلیدِ کامل (ورود با رمز) هم این‌ها را دارد.

### `POST /sms/claim`  ‌ `{nonce}`
بی‌کلید. کدی که خودِ اپ ساخته و صفحه‌ی واردشده با `api/sms_link.php` به کاربرِ
نشست بسته است → `{token, username}`، **یک بار**. هنوز بسته نشده/منقضی/گرفته‌شده:
۴۰۴؛ بدشکل: ۴۲۲.

### `GET /sms/wallets`
همان `walletSmsKeys()`ِ سایت: `[{id, card4, acct4, banks}]` — فقط چهار رقمِ آخر.

### `POST /sms/tx`
`{type, amount, date, wallet_id, how, balance, note, fp, sms_at}` — فیلدهای
`smsWorker().post` به‌علاوه‌ی اثرِ انگشت (`fp`، هشت رقمِ hex) و زمانِ رسیدن
(میلی‌ثانیه). **متنِ پیامک هرگز.** ۲۰۱ ثبت شد؛ ۲۰۰ با `duplicate: true` و شناسه‌ی
همان تراکنش اگر این اثرِ انگشت پیش‌تر ثبت شده؛ ۴۲۲ حسابِ غیرِ خودی یا مقدارِ
نامعتبر. `balance_set` می‌گوید مانده نشست یا نه (فقط `how` ∈ card/acct/bank و
پیامکِ تازه‌تر از آخرین مانده‌ی همان حساب).

## نمونه با curl

```bash
BASE=https://hesab.stland.ir/api/v1

TOKEN=$(curl -s -X POST -H 'Content-Type: application/json' \
  -d '{"username":"ali","password":"...","platform":"android"}' \
  "$BASE/auth/login" | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

curl -s -H "Authorization: Bearer $TOKEN" "$BASE/dashboard"
```

### ⛔ تله‌ی nginx که یک بار خوردیم

قاعده باید `location /api/v1/` باشد، **هرگز `location ^~ /api/v1/`**.

`^~` به nginx می‌گوید «اگر این prefix برنده شد، دیگر location های regex را نگاه نکن» —
و `location ~ \.php$` هم یک regex است. نتیجه: nginx فایل PHP را به‌جای اجرا **خام**
تحویل می‌دهد و `/api/v1/ping` سورس کامل `index.php` را برمی‌گرداند.

`nginx -t` سبز می‌ماند و `reload` هم موفق می‌شود، پس هیچ ابزاری جلویش را نمی‌گیرد.
`deploy/nginx-api.sh` حالا بعد از اعمال، خودِ اندپوینت را صدا می‌زند و اگر سورس یا
چیزی جز JSON دید، پیکربندی را برمی‌گرداند. قاعده ۱۰ در `test_api_contract.php` هم
وجود `^~` را در اسکریپت‌ها ممنوع می‌کند.
