# حساب لند

اپلیکیشن حسابداری شخصی و خانوادگی — چندکاربره، فارسی و راست‌به‌چپ، با تاریخ شمسی.
موبایل‌فرست و قابل نصب روی گوشی (PWA).

PHP خام (بدون فریم‌ورک و بدون Composer) + MySQL/MariaDB + PDO.

---

## چه کارهایی می‌کند

| بخش | کار |
|---|---|
| **تراکنش‌ها** | ثبت درآمد و هزینه با دسته‌بندی، حساب، پیوست و جست‌وجو |
| **حساب‌ها** | چند حساب (نقدی / بانکی / سایر)، نمای کارت بانکی، انتقال بین حساب‌ها، تعدیل موجودی |
| **گزارش‌ها** | داشبورد با بازه‌ی دلخواه، گزارش دسته‌بندی، مقایسه‌ی ماه‌ها، خروجی اکسل |
| **بودجه** | سقف ماهانه به تفکیک دسته با نمایش پیشرفت |
| **پس‌انداز** | هدف پس‌انداز با تاریخچه‌ی واریز |
| **چک** | چک دریافتی و صادره، سررسید، پاس‌شدن با انتخاب حساب |
| **طلب و بدهی** | پرداخت جزئی و تسویه‌ی کامل، گردش هر طرف حساب |
| **دارایی** | نمای ترکیب دارایی با نمودار، و کلید روشن/خاموش برای هر قلم |
| **معاملات** | دفتر خرید و فروش جدا از درآمد/هزینه (اختیاری، هر کاربر برای خودش) |
| **تکرارشونده** | تراکنش‌های دوره‌ای که خودکار ثبت می‌شوند |
| **تقویم** | رویدادهای مالی روی تقویم شمسی |
| **فهرست‌های من** | بانک‌ها، انواع دارایی، انواع حساب، اشخاص، و دسته‌بندی شخصی |
| **کاربران** | چند کاربر با نقش مدیر/کاربر، داده‌ی هر کس کاملاً جدا |

ورود با نام کاربری یا ایمیل، بازیابی رمز از ایمیل، «این دستگاه را ۳۰ روز به خاطر بسپار»،
و سدِ حدس رمز روی صفحه‌ی ورود.

## نصب

**راهنمای کامل و تنها راه پشتیبانی‌شده: [`DEPLOY.md`](DEPLOY.md)**

خلاصه‌ی مسیر:

```bash
# ۱. گزارش وضعیت سرور پیش از هر تغییر (فقط می‌خواند)
sudo bash deploy/vps-preflight.sh

# ۲. نصب — بدون --apply فقط نشان می‌دهد چه می‌کند
bash deploy/vps-setup.sh --domain example.com
sudo bash deploy/vps-setup.sh --domain example.com --apply

# ۳. ساخت جدول‌ها
bash deploy/migrate.sh            # وضعیت
bash deploy/migrate.sh --apply    # اعمال
```

بعد آدرس سایت را باز کنید؛ چون هنوز کاربری نیست، به `setup.php` می‌روید تا حساب مدیر را بسازید.

`config/config.php` را از روی `config/config.example.php` بسازید. این فایل و پوشه‌ی `uploads/`
هرگز وارد گیت نمی‌شوند و در به‌روزرسانی دست‌نخورده می‌مانند.

### به‌روزرسانی

```bash
cd /opt/hesab/app && git pull && ./deploy.sh
```

## ابزارهای نگهداری

همه در `deploy/` هستند و همه فقط از خط فرمان اجرا می‌شوند:

| اسکریپت | کار |
|---|---|
| `migrate.sh` | اعمال migration با ردیابی و بررسی چک‌سام (`--apply`, `--verify`, `--baseline`) |
| `backup.sh` | بکاپ دیتابیس (`--install-cron` برای بکاپ روزانه) |
| `restore.sh` | **سنجش و بازیابی بکاپ** — پیش‌فرض روی دیتابیس موقت می‌آزماید و به داده‌ی زنده دست نمی‌زند |
| `perf-report.sh` | تشخیص علت کندی: سیستم، opcache، pool، کش، دیتابیس، و زمان پاسخ از روی خودِ سرور |
| `user-admin.php` | مدیریت کاربر از خط فرمان (`--reset`, `--unlock`, `--set-email`) |
| `tune.sh` | تنظیم pool پی‌اچ‌پی روی نصب موجود |
| `nginx-perf.sh` | روشن کردن HTTP/2 |
| `nginx-sw.sh` | افزودن استثنای سرویس‌ورکر به nginx |
| `nginx-api.sh` | آدرس تمیز برای `api/v1` |
| `mail-setup.sh` | تنظیم ارسال ایمیل (`mail()` یا SMTP) |
| `vps-preflight.sh` | گزارش وضعیت سرور پیش از نصب |

اسکریپت‌هایی که چیزی را عوض می‌کنند بدون آرگومان **فقط نمایش می‌دهند**؛ اعمال با `--apply` است.

## ساختار

```
config/       تنظیمات (فقط config.example.php در گیت است)
includes/     لایه‌ی مشترک — همه‌ی صفحه‌ها از اینجا شروع می‌شوند
api/          اندپوینت‌های AJAX خودِ سایت (داخلی)
api/v1/       API نسخه‌دار با توکن، برای اپ موبایل — docs/API.md
admin/        صفحه‌های ویژه‌ی مدیر
assets/       CSS، JS، آیکون‌ها، فونت وزیرمتن (همه از خود سرور، بدون CDN)
deploy/       ابزارهای نصب و نگهداری
docs/         مستندات — از جمله مرجع API
tests/        مجموعه تست
*.php         صفحه‌های کاربر
*.sql         schema.sql + ۱۹ فایل migration
```

## اپ موبایل

`api/v1` یک API نسخه‌دار با احراز هویت توکنی است که اپ اندروید و iOS روی آن می‌نشینند.
وب همچنان مستقیم با PHP کار می‌کند و به این لایه نیازی ندارد.

**مرجع کامل برای کسی که اپ را می‌نویسد: [`docs/API.md`](docs/API.md)**

```bash
curl -s https://example.com/api/v1/ping
```

## تست

```bash
bash tests/run.sh
```

۱۳ مجموعه تست؛ کد خروج باید صفر باشد. **پیش از هر push اجرا شود.**
بررسی نحو داخل همین مجموعه هست، پس `php -l` جدا لازم نیست.

⚠️ تست‌ها روی **همان دیتابیسی** اجرا می‌شوند که در `config/config.php` تعریف شده. کاربر و
رکوردهای موقتِ خودشان را با پیشوند `__test_` می‌سازند و آخر کار پاک می‌کنند، ولی جای اجرایشان
دیتابیس توسعه است نه دیتابیس زنده. اگر ناچار شدید روی سرور اجرا کنید، اول `deploy/backup.sh`.

هر فایل داخل `tests/` و `deploy/` نگهبان `PHP_SAPI !== 'cli'` دارد تا از راه وب قابل اجرا نباشد —
این پوشه‌ها داخل ریشه‌ی وب‌اند و nginx هم جداگانه مسدودشان می‌کند.
